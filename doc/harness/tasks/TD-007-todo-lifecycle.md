# TD-007：正式待办、完成操作与来源生命周期

- 状态：DRAFT；等待 [Phase 2 方案](../MVP_PHASE2_PLAN.md) 实施批准。
- 里程碑：P2-M3；依赖：TD-001、TD-006；来源清理依赖 NI-006。

## 目标

让已确认任务可查看、可完成、可跨进程保存，并在原通知过期后保留用户的正式任务。

## 实施要点

- 提供已确认未完成 / 已完成视图；确定日期先排序，无日期置后，相同排序条件使用稳定次序；模糊短语不伪装成确定截止。
- 完成操作经业务服务执行，重复操作幂等；首版不提供撤销完成、周期任务和自动提醒。
- 接入 NI-006 清理：原始快照、消息正文和未确认候选遵循来源保留期；正式任务保留用户确认的行动内容。
- 不把完整消息正文复制进永久任务字段以规避清理；原来源过期后关系可空，页面说明原通知已清理。
- 忽略的轻量抑制记录与可重放来源保持一致的有效期；确认与清理并发事务化，避免误删或半成品。
- 复核新表 / 配置均受本地隐私与备份规则覆盖，不只检查旧 notification_snapshots。

## 验收

| 场景 | 判据 | 状态 |
| --- | --- | --- |
| 查看 / 完成 / 重开 | 排序与状态一致，无自动确认 | NOT_RUN |
| 原始通知清理后看正式任务 | 任务仍在，完整原文不再可读，来源过期可解释 | NOT_RUN |
| 未确认 / 忽略来源过期 | 按策略清理正文与相关临时内容 | NOT_RUN |
| 确认与清理并发 | 先确认则保留，先清理则明确失败，不误删正式任务 | NOT_RUN |
| 旧库升级与新数据备份 / 恢复 | 兼容且符合本地数据契约 | NOT_RUN |

Verify + Room / UI / Device 验证，覆盖 P2-V08、P2-V11、P2-V12。保存任务不代表批准向外同步或发送原文。
