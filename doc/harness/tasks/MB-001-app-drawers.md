# MB-001：按 App 分抽屉的消息盒子

- 日期：2026-09-22；状态：DRAFT；范围见 [产品 MVP](../MVP_PRODUCT_PLAN.md)。
- 依赖：TD-001 / TD-002 的消息与存储契约，NI-006 读取 / 清理接口；使用现有 Compose / Room / Repository。
- 实施基线：开工时重新核对 STATE 和源码；本次只拆解，不创建数据库表或页面代码。

## 目标与范围

现有通知入口升级为消息盒子，每个获准 App 一个抽屉，展开查看稳定消息；保留详情溯源和 MB-002 的跳转事件。不把快照观察次数当消息数，不再复制一套通知收集器。

## 契约与实现位置

- 以 TD-002 的稳定消息 ID / 版本、来源包与可靠用户资料归属分组；没有可靠资料标识时不得合并分身或工作资料。来源显示名和图标只用于展示。
- 抽屉显示最新摘要及本地待查看消息数；尚未收到消息的选定来源显示真实空态。关闭来源后历史仍可见，标记停止收录，继续遵守原保留期。
- 按实际观察时间排序；同消息重放不增加数量，不同内容的新有效版本可重新进入待查看。身份不确定时遵守 TD-002 的保守规则，不凭同文合并。
- 建议以 messageId / version 持久化本地查看依据；只有行实际进入可见区域、打开详情或点击该行请求跳转时才标该版本已查看。仅进入盒子或展开抽屉，不把屏幕外消息批量清零；滚动和并发新消息有确定性验收。
- “已查看”“已请求打开”与 AI 状态 / 待办状态分开。来源原 App 的未读和已回复不参与本地推断。
- UI 经 ViewModel / Repository 读取展示模型，不新增 Entity / DAO 直连。数据、迁移、清理与计数放共享层；新增 Kotlin 字段 / schema 是实现事实来源。
- 正文过期时删除相关查看元数据或按明确清理策略回收；正式待办不级联删除。隐藏 / summary / 缺正文行显示原始可用性，不猜聊天内容。
