# TD-003：共用 AI 提取契约、校验与规则对照

- 状态：DRAFT；等待 [Phase 2 方案](../MVP_PHASE2_PLAN.md) 实施批准。
- 里程碑：P2-M2；依赖：TD-000 样本、TD-001 输入输出契约；可先使用合成输入。

## 目标

定义本地 / 云端共用的提取输入输出与结构 / 证据校验，结果为 ACTIONABLE / NOT_ACTIONABLE / UNSURE、0..n 条行动建议及来源依据。小型 RuleBasedTodoExtractor 用于合成测试和效果对照，不再作为唯一生产提取路线。具体引擎在 [AI-002 / AI-003](../../product/AI/IMPLEMENTATION.md) 实现。

## 实施要点

- 优先确认请求对象与行动，不凭时间词创建待办；保留否定、对方承诺、广告 / 验证码和对象不明群聊的排除或不确定路径。
- 标题只规范化原文已支持的动作和对象；“给我”与发送人的关联必须有来源依据，不猜联系人身份。
- 多行动拆分仅支持有明确边界的句式，每项都指向原文范围；复杂句子返回不确定，不通过任意标点无限切分。
- 保留原始时间短语交给 TD-004；模型返回的日期也需按固定锚复核，不直接作为可信 dueAt。
- 输出结构 / 原文证据校验独立于匹配逻辑；解析错误可诊断，取消不被降级吞掉。

## 验收

| 输入 | 判据 | 状态 |
| --- | --- | --- |
| “请你明天发报价单给我” | 行动建议与原文一致 | NOT_RUN |
| “我明天发给你”、否定请求、非任务通知 | 不因关键词误建用户任务 | NOT_RUN |
| 执行对象不明的群消息 | UNSURE，不猜测指定用户 | NOT_RUN |
| 明确双行动、复杂含糊句子 | 前者可独立追溯，后者保留不确定 | NOT_RUN |
| 返回不存在的证据 / 空标题等异常结果 | 结构或证据检查拒绝 | NOT_RUN |

Verify 中的纯函数回归覆盖 P2-V01–V04 与 AI-V05；畸形、无证据、注入和截断结果不可伪装有效提取。记录误报 / 漏报；规则或模型分数不是校准概率。本任务不引入运行时或 HTTP，不写数据库；应用端校验不能代替真实模型质量验收。
