# TD-006：候选收件箱与用户确认

- 状态：DRAFT；等待 [Phase 2 方案](../MVP_PHASE2_PLAN.md) 实施批准。
- 里程碑：P2-M3；依赖：TD-001 状态服务、TD-005 候选处理。

## 目标

用户能审阅建议、查看来源证据，修改标题 / 截止后确认，或忽略。用户行为决定是否成为正式任务。

## 实施要点

- 在现有导航增加任务入口，候选与正式待办使用明确分区；保留通知诊断、状态、来源设置的可达性。
- 展示建议标题、来源、短证据、命中原因、截止精度 / 待确认提示；原文从受控来源读取，不为 UI 缓存永久复制正文。
- 提供编辑确认 / 忽略，验证非空标题和合法时间；日期型允许保持日期精度，不强迫用户选虚构时刻。
- UI 调用应用服务 / Repository，不直接操作 DAO。处理中防误操作，真实并发保护仍在业务层。
- 处理加载、空、失败、候选已过期、旧版本冲突；提交失败时保留用户编辑，不虚假显示确认成功。

## 验收

| 操作 | 判据 | 状态 |
| --- | --- | --- |
| 看到 ACTIONABLE 建议但未确认 | 不出现在正式待办列表 | NOT_RUN |
| 修改标题 / 时间后确认 | 保存用户版本，状态 CONFIRMED | NOT_RUN |
| 双击、确认 / 忽略竞争、晚到规则结果 | 一个合法结果，无覆盖和重复 | NOT_RUN |
| 提交失败 / 候选清理后仍在页面 | 失败可见、编辑不丢或过期可解释 | NOT_RUN |
| 忽略后重开与输入重放 | 不再次出现相同候选 | NOT_RUN |

Verify + UI / Device 证据，覆盖 P2-V01、P2-V08、P2-V09、P2-V11。批量确认、恢复忽略与手动新建任务不属于首版。
