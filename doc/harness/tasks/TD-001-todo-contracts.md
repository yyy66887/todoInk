# TD-001：建立消息、候选与任务状态契约

- 状态：DRAFT；等待 [Phase 2 方案](../MVP_PHASE2_PLAN.md) 实施批准。
- 里程碑：P2-M1；依赖：TD-000 的输入契约；迁移必须基于已确定的 Phase 1 schema。

## 目标与范围

引入 ObservedMessage、消息与快照关系、提取记录、TodoItem，以及相应 Repository / 状态应用服务。数据与状态逻辑不放在 Compose 页面。

## 实施要点

- 按方案定义身份、正文、原始来源关系、规则版本、时间精度、用户编辑版本；不强制套用早期 PRD 的简化示例字段。
- 四态转换仅允许 CANDIDATE → CONFIRMED / IGNORED、CONFIRMED → COMPLETED。重复同一操作幂等，其他非法转换返回明确结果。
- 更新带预期版本或等价并发保护；确认 / 忽略竞争只允许一个合法结果，失败不留下多份正式任务。
- 定义精确时刻、仅日期、模糊 / 无截止的表示；不为日期型任务写入虚构的 23:59。
- 定义来源过期后保留正式任务、删除未确认内容的关系与事务策略；执行清理由 TD-007 接入。
- schema 递增、保留历史导出、提供迁移；不预设 Phase 1 完成时一定仍是 v1。新业务包按实际依赖登记边界并自测。
