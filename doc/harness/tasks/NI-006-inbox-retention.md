# NI-006：完成 Inbox、诊断详情与保留期

- 状态：READY（2026-09-20 Phase 1 v0.1 获批，见方案第 9 节审核记录）。
- 里程碑：M3；优先级：P0；依赖：NI-002、NI-003、NI-004、NI-005。
- 契约：C07、C09–C12；场景：V10–V13。

## 目标

用户能看到已保存内容，区分原始字段与解析结果，排查内容不足，选择保留期并验证清理行为。通知仅保存在本地的承诺有配置与行为证据支持。

## 两步交付

### A：Inbox 与详情

- 列表按 receivedAt 倒序展示来源、标题、可用正文、时间、版本与观察次数；Raw / Normalized 详情展示 NI-003 持久化的受控字段与 0..n 消息。
- 区分加载中、空、读取失败、内容隐藏与 summary；来源名称不可取时可退回包名，未知发送人 / 会话不猜测。
- UI 使用 Repository 暴露的读取模型；移除 NotificationsViewModel / NotificationsScreen 到 Entity 的两项历史例外。NI-005 的 DAO 例外应已清理。
- 保留既有页签结构与导航；不增加候选任务或硬件页面。

### B：生命周期与隐私

- 默认保留 3 天，设置可选 1 / 3 / 7 / 30 天；处理旧设置值的展示兼容，不静默缩短用户已有合法设置。
- 启动、保留期修改以及持续采集的受控频率触发清理；页面不展示已过期项，日期边界由可注入时钟验证。
- 明确进程未运行时下次清理才物理删除的限制，首版不承诺精确后台删除。
- 复核整个读取 / 清理过程不破坏迁移与字段往返；备份配置合法且覆盖通知库 / 设置，并在可用测试环境验证恢复行为。

范围：ui/notifications、ui/settings、导航、Repository 读取模型、Settings、清理调度与备份配置；必要 schema 变更使用增量迁移。保留期清理只针对原始快照，不预先定义未来 TODO 删除规则。
