# NI-007：三款来源验收与 Phase 1 出包

- 状态：READY（2026-09-20 Phase 1 v0.1 获批，见方案第 9 节审核记录）。
- 里程碑：M4；优先级：P0；依赖：NI-000–NI-006 全部所需交付。
- 基准：PRD §23–24、CONTRACTS C01–C12、VERIFICATION V01–V13。

## 输入与范围

输入是当前源码、软件检查结果、待验 APK 和一台条件明确的测试手机；设备安装微信、企业微信、QQ，并由测试者准备可控会话。此任务不自动联系真实联系人、不收集完整私人聊天。

## 执行步骤

1. 从当前代码重新运行 Static / Verify / Device，保存非空报告、APK 路径、版本、构建时间与 SHA-256。
2. 安装并检查授权、选择来源、关闭 / 重开、数据库升级与保留期等跨功能流程。
3. 三款来源各执行下列 8 类场景。记录实际字段、系统是否产生通知及 TodoInk 行为，不把“没有系统通知”当成功捕获。
4. 发现应用缺陷回到所属 NI 任务修复，复跑受影响用例；不靠删除失败场景或放宽断言收口。
5. 输出设备矩阵、产品限制、未完成项和阶段结论；通过后更新 STATE，停止在 Phase 1 边界。

## 完成条件

- 每款来源至少一次真实可见正文的捕获、保存、重开可查看证据；24 格无未说明的空白。缺来源 / 账号的格子保持 NOT_RUN / BLOCKED，不能声称全部验收。
- V01–V13 所需证据齐全，无隐私边界、数据丢失、重复灌库、状态误导或静默丢弃等未解决阻断问题。
- debug APK 可安装启动，交付说明写明适用设备范围、来源限制、旧库迁移与保留期行为。
- 代码完成、自动检查通过、真机验收完成分别记录。任务 DONE 不自动批准 Phase 2 或公开发布。

交付证据保存到 `doc/harness/evidence/`，通知文本与设备可识别信息按实际需要脱敏。没有真机证据时保留待验状态。
