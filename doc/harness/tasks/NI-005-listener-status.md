# NI-005：让来源设置、授权与采集状态真实可见

- 状态：IN_PROGRESS（2026-09-20 开始执行）。第 1 步（独立授权读取与分离展示）与第 4 步（Repository 计数、移除 DAO 例外）已由 [UI-B](UI-B-notification-detail.md) 实现并通过软件门禁；第 2 步（启动恢复竞态 / 节流持久化）与第 3 步（来源开关提交状态）未实施。验收场景 NOT_RUN，待设备验证。
- 里程碑：M1；优先级：P0；依赖：NI-001、NI-000。
- 契约：C01、C02、C09、C11；场景：V08 及 V01 / V02 的用户操作。

## 当前问题与目标

状态页以 listenerConnected 代替授权状态；启动时持久化状态恢复可能覆盖已发生的连接变化；最近回调只有内存更新。来源列表与设置操作的加载、失败、提交成功语义需要分开。

目标是让用户知道“是否已授权、是否已连接、最近是否收到并保存”，并能明确开始 / 停止选定来源的采集。

## 范围与步骤

1. 在系统适配边界独立读取通知访问授权状态；从系统设置返回后刷新，与监听连接分别展示。
2. 修复 ListenerStatusStore 的启动恢复竞态；恢复历史时间不覆盖本次连接 / 回调状态。采用适当节流持久化诊断时间，不在每条回调中阻塞写盘。
3. 来源选择默认关闭；将应用列表的加载、空、失败和开关提交状态分别表达；失败不显示“已关闭”。文案与 NI-001 实际行为一致。
4. 记录数通过 Repository 查询，移除 StatusViewModel 到 DAO 的精确历史例外，同时更新边界说明。

主要位置：ui/status、ui/settings、data/settings、data/repository 与系统授权查询适配。页面不直接实现存储或通知解析。
