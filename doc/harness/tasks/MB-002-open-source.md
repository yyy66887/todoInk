# MB-002：点击消息打开来源 App

- 日期：2026-09-22；状态：DRAFT；范围见 [产品 MVP](../MVP_PRODUCT_PLAN.md)。
- 依赖：TD-002 的消息 / 快照关系、MB-001 点击入口、NI-001 来源与监听连接边界。
- 实施基线：开工时重新核对当前源码；本轮只有方案，没有运行 PendingIntent 或发送消息。

## 目标与范围

用户在 App 抽屉点击一条消息，请求打开来源 App 为该通知定义的目标；入口失效时提供准确降级。遵守用户已选择的“回原 App 回复”，不引入 RemoteInput 发送、无障碍或私有会话 URL。

## 契约与实现位置

- notification 系统适配层在允许来源内管理当前点击能力，或连接后按 key 重新取得当前通知；通知更新、移除、断连和来源撤销使旧能力失效。入口变化不能仅靠 Room 正文去重事件驱动。
- 身份绑定来源包、可验证用户资料、通知 key 和观察代次；从消息通过实际溯源关系定位通知，不能取同 App 最新通知冒充原消息。通知已更新且不能确认目标关系时降级。
- 使用原通知 contentIntent，不构造对方私有组件 Intent；运行时句柄仅在系统适配层，不放入 Draft、Room、AI 请求或普通日志。
- 用户前台点击才启动；先复核当前来源 / 身份，处理取消、权限或系统启动失败。遵守 FLAG_AUTO_CANCEL 等通知点击语义，但移除通知不意味着回复完成。
- 原通知提供的目标可能是会话、列表或首页。界面使用“打开来源 App”等准确文案；有适配证据时才表述直达会话。
- TodoInk 验证的是点击能力与来源消息的关联，无法保证来源 App 内部路由永不变化；兼容性报告分别记录本应用关联是否正确与来源最终打开位置。
- contentIntent 不可用时提供可见的打开 App 降级，安装状态 / 用户资料受限时说明不可用，不跨资料启动同名应用；无可用入口保留查看原文能力。
- 记录尝试与可观察结果，不能把 send() 返回、返回 TodoInk、停留时间或通知消失记为已回复 / 已送达 / 待办完成。
- 重复点击合并当前打开操作，失败可由用户再次操作；页面跳转和状态保存不依赖主线程长任务。来源变更与准入有明确边界，已经提交的启动无法保证撤回。
