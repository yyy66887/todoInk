# TD-004：可解释的截止时间解析

- 状态：DRAFT；等待 [Phase 2 方案](../MVP_PHASE2_PLAN.md) 实施批准。
- 里程碑：P2-M2；依赖：TD-000 时间样本、TD-001 时间结果契约。

## 目标

从时间短语、固定消息时间锚和时区上下文生成截止建议，表达日期、精确时刻、模糊或没有截止；相同输入重放保持一致。

## 实施要点

- 首版支持今天 / 明天 / 后天、明确日期与时刻；周几按冻结的语义解析，跨周与“本周 / 下周”分别处理。
- 提取前固定锚点：可信原始消息时间优先，其次首次观察时间，并保存依据；不要直接用调用时的系统时间解释历史消息。
- 复用 AppClock 支持测试；时区作为显式输入或最小可注入接口，不把设备当前时区静态写死为所有用户的时区。
- “下午”“下班前”、缺年份日期、节假日 / 工作日等未支持表达保留原短语与待确认提示。过去时刻不自动顺延；日期型不伪造成精确时刻。
- 时区未知、夏令时缺失 / 重复时刻和无效日期返回明确的歧义 / 错误结果，不悄悄采用平台默认修正。

## 验收

| 场景 | 判据 | 状态 |
| --- | --- | --- |
| 固定 2026-09-20 10:00 +08:00，“明天15点前” | 2026-09-21 15:00 +08:00，隔天重放不变化 | NOT_RUN |
| 仅日期、模糊时段、无截止 | 精度正确，dueAt 不被随意填充 | NOT_RUN |
| 跨月 / 年、周边界、过去时间 | 与书面规则一致，可解释 | NOT_RUN |
| 时区变化或无法恢复历史时区 | 不覆盖已解析的原锚结果，不伪造历史信息 | NOT_RUN |
| 无效日期 / 夏令时边界 | 明确拒绝或待确认，无隐式纠正 | NOT_RUN |

Verify 中的纯函数测试覆盖 P2-V06、P2-V07。输出仍是候选建议，由用户最终确认；此任务不创建提醒或系统日历事件。
