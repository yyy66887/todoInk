# TD-002：通知快照投影为可追溯消息

- 状态：DRAFT；等待 [Phase 2 方案](../MVP_PHASE2_PLAN.md) 实施批准。
- 里程碑：P2-M1；依赖：TD-001，NI-003 / NI-002 的已验证输入与持久化接口。

## 目标

将受控快照中的 0..n 消息投影为 ObservedMessage，保留来源关系，避免把每次系统通知更新都当作新任务输入。

## 实施要点

- 复用 Phase 1 的解析结果和字段选择规则，不在投影层重写第二套厂商解析逻辑。
- 同快照 / 段落重复投影使用稳定关联；跨快照只在消息身份有足够证据时复用，不按全文或标题全局合并。
- 保留同一消息被多个快照观察到的关系；重复文本的不同出现次数不能被集合去重吞掉。
- 明确弱身份策略：缺会话 / 原始消息时间时保留不确定性，宁可标待核对，也不静默合并独立请求。
- 保存首次时间锚与实际时区依据。已丢失的历史时区不能通过当前设备设置伪装恢复。
- summary / 隐藏无正文只保留诊断，不投影出臆造的可识别消息。

## 验收

| 场景 | 判据 | 状态 |
| --- | --- | --- |
| 同一快照重复处理 | 消息和来源关系数量稳定 | NOT_RUN |
| 可信消息列表 A→A+B | A 复用身份，B 新增，来源关系完整 | NOT_RUN |
| 不同 App / 会话同文；不同时间重复同一句 | 不错误合并独立消息 | NOT_RUN |
| 缺身份字段、正文重复出现、summary | 保留不确定性 / 重复出现次数，不补造字段 | NOT_RUN |
| 进程重建再次投影 | 身份、时间锚和关联保持一致 | NOT_RUN |
