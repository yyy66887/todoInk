# TD-005：可靠地处理并写入候选待办

- 状态：DRAFT；等待 [Phase 2 方案](../MVP_PHASE2_PLAN.md) 实施批准。
- 里程碑：P2-M3；依赖：TD-002–TD-004、AI-001；联调先接 AI-002 / AI-003 中就绪的引擎，阶段验收需二者；真实链路仍依赖相关 NI。

## 目标

建立消息 → 选定 AI 引擎 → 结构 / 证据 / 时间校验 → 候选的统一应用服务，自动处理和恢复都经过同一入口；提取失败不影响原通知采集。遵守 [AI-C01–AI-C08](../../product/AI/README.md)。

## 实施要点

- 接入 AI 模块的模式与自动处理开关，默认关闭；开启时保存起点，只处理此后新观察到的合格消息，不自动回填历史或跨新配置重发积压。
- 采用持久化处理进度 / 记录，候选写入与成功标记具备事务保证。不能仅依赖一条可能丢失的内存事件，或全表每次无条件扫描。
- 同消息 / 行动的重放幂等；规则、模型或提示模板升级不重建已确认 / 已忽略 / 已完成任务，也不覆盖用户编辑。记录新建议与有效版本，历史重算以后单独设计。
- 云端发出前复核配置与来源；准备写入时复核开关、来源、输入 / 配置版本与有效期。配置更新和准入 / 提交分别具有明确串行化边界；迟到失效结果丢弃，已提交正式任务不自动删除。
- 取消继续传播；失败保存结构化原因与有限恢复策略；不能无限重试或把异常标成识别成功。
