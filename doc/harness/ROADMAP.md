# 阶段与任务队列

本清单是可接手的开发顺序。当前完成状态和软件 / 设备证据统一见 [STATE](STATE.md)，不因文档或骨架存在就把产品能力标记为完成。

2026-09-22 产品主线已按用户澄清收束为 [消息整合 → AI → TodoList → 后续墨水屏](../product/TodoInk_核心闭环可行性与验证路线.md)。消息盒子按获准 App 分抽屉，点击跳转原 App；用户已否决 TodoInk 内直接回复。完整发出消息采集不作为 TD / AI 前置，也不新增消息发送阶段。

当前可审核范围与交付批次统一在 [产品 MVP v0.1](MVP_PRODUCT_PLAN.md)：MVP-M0 基线 → M1 消息盒子 → M2 首个 AI 引擎 → M3 手机清单闭环 → M4 双模式与试用验收。复用 NI / TD / AI，仅新增 [MB-001](tasks/MB-001-app-drawers.md) / [MB-002](tasks/MB-002-open-source.md)；最终交付包括两种 AI，硬件后置。

据已保存批准记录，[Phase 1 方案](MVP_PHASE1_PLAN.md) v0.1 已获批。[Phase 2 方案](MVP_PHASE2_PLAN.md) 已升为 v0.3，包含 AI 与消息盒子；TD-000–TD-008、MB-001 / MB-002、AI-001–AI-005 仍为待审核实施任务，本轮只交付方案。

## Harness 后续演进

1. 建立 Git / CI 后接入现有检查入口和证据报告，不再另写一份规则。
2. 首批任务完成后，把重复且高价值的行为约束变成生产测试；记录反馈耗时与接手耗时。
3. 出现第二个确实复用同一契约的用例再提炼共享模块。
4. 全量检查确实过慢时再做影响分析；未知输入必须扩大检查或失败。
5. 只有出现持续自动执行需求，才设计工具元数据、超时 / 取消、执行记录、预算与终态组成的执行器。当前不实现通用 AgentLoop。
