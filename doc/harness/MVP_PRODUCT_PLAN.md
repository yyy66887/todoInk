# TodoInk 产品 MVP：消息盒子 → AI → TodoList

- 版本：v0.1；日期：2026-09-22；状态：DRAFT，供用户审核，尚未启动新增功能实施。
- 用户目标：整合获准 App 的通知，利用 AI 整理待办，在手机形成可用清单，后续扩展墨水屏。
- 本文统一首版产品范围、交付顺序和发布标准；底层采集继续遵守 [Phase 1](MVP_PHASE1_PLAN.md)，消息 / 候选契约继续遵守 [Phase 2](MVP_PHASE2_PLAN.md)，模型细节见 [AI 模块](../product/AI/README.md)。不重置已有任务和授权。
- 依据：[核心闭环研判](../product/TodoInk_核心闭环可行性与验证路线.md)、[消息盒子规格](../product/TodoInk_消息盒子与发出消息可见性.md)、本轮源码检查；工作入口为 [AGENTS.md](../../AGENTS.md)。

## 1. MVP 要验证什么

**用户能把分散在多个 App 通知中的明确行动项，低成本地整理为一份可追溯、可管理的清单。**

首版终点为 Android 手机端完整闭环：

**允许来源 → 收录通知 → 按 App 分抽屉 → AI 生成候选 → 用户确认 / 忽略 → 正式待办 → 用户完成。**

消息盒子可随时跳转来源 App 查看 / 回复。这个动作不等于已经回复或完成任务；获取完整双向聊天不是 MVP 前置。

首个使用人群为用户本人，首要内容为中文工作消息；来源重点验证微信、企业微信、QQ，通用采集仍适用于用户选择的其他 App，但未经实测的来源不标记为已支持。首个设备基线建议沿用项目中测试过通知存储的 OnePlus PJZ110；实施前重新核对系统、RAM、空间与连接条件，不能把旧存储测试当成模型兼容证明。

## 3. 首版范围

| 功能 | P0 必须交付 | 本版边界 |
| --- | --- | --- |
| 来源与采集 | 用户选择来源；权限和监听状态分开；可读正文保留 / 去重 / 清理 | 收录实际可见通知，不宣传完整聊天同步 |
| 消息盒子 | 每个 App 一个抽屉，最新摘要、本地待查看数、消息列表和详情 | 普通个人资料优先验证；工作资料 / 分身有可靠身份才隔离支持，否则明确限制，不混合 |
| 跳转原 App | 点击消息使用当前有效入口，失效时降级打开 App 或说明原因 | 不保证历史通知直达会话，不在 TodoInk 内发送 |
| AI | 本地一个经真机验证的模型组合；云端一种兼容协议和可配置服务 | 单活动引擎；不做模型商城、多引擎投票或自动切云端 |
| 候选 | 建议标题、可选截止、来源证据；编辑标题 / 时间、确认或忽略 | 有歧义时交给用户，不能强造执行人或时间 |
| TodoList | 今天 / 全部 / 已完成；详情溯源；用户标记完成 | 首版仅四态，不增加项目协作、周期任务或自动完成 |
| 可靠性 | 重启恢复、幂等、取消、配置变化、保留期与来源过期提示 | AI 失败不影响通知采集，失败不冒充非任务 |
| AI 状态与隐私 | 来源单独允许、真实处理状态、模型 / API 自检、受保护 Key、用量边界 | 本地不外发，云端只发获准内容；普通日志无正文 |

墨水屏、BLE / ESP32 固件、日历 / 提醒、手工新建与分享导入、批量历史重算、跨 App 自动合并、无障碍抓取、完整发出消息采集、自建账号 / 云同步均后置。后置项不在页面放成可用功能。

为保持双模式可交付，本地首版只承诺一个锁定模型 / 量化 / 运行时组合在已验目标设备上可用；云端只承诺兼容适配器及已验服务，不能宣传任意地址、任意模型都兼容。模型选择依据保留在 AI 模块，本文不另维护型号清单。

## 4. 页面和默认策略

底部入口为 **待办 / 待确认 / 消息盒子 / AI / 设置**，默认进入待办。沿用现有纸白 / 墨黑 / 紫色视觉，五入口需验证窄屏和大字体。主链不增加独立聊天页。

| 页面 | 用户最重要的动作 |
| --- | --- |
| 消息盒子首页 | 展开某 App 抽屉，查看最近消息与待查看数量 |
| App 抽屉 | 点击一条消息跳转原 App；独立“详情”入口查看保留期内原文 |
| 待确认 | 查看建议、修改标题 / 时间，确认或忽略；一条消息可有多项行动 |
| 待办 | 今天优先展示逾期 / 今日事项；全部可看未来和无截止任务；完成后移入已完成 |
| AI | 选择本地 / 云端、配置引擎与允许来源、开启自动处理、查看失败原因 |
| 设置 | 通知来源、授权 / 连接、保留期与关于 |

默认值建议：

- 采集来源、AI 处理来源、云端发送来源都由用户选择；AI 自动处理默认关闭。配置测试只用内置合成样本，不等于开启自动发送。
- 开启后只处理新观察到的合格消息，不回填历史；换模式先停用，重新开启后只处理后续新消息。
- 通知、原文与未确认候选默认保留 3 天；正式任务保留标题和必要摘要，原文清理后提示来源已过期。保留期沿用现有设置与 Phase 2 清理契约。
- 普通通知缺正文、摘要通知或不确定行动保留明确状态；未查看数只描述 TodoInk 内的查看，不对应来源 App 的未读数。
- 本地模型不可用则暂停；云端超时 / 限流可诊断。不能因失败改用另一服务，也不能通过重启重置本地配额。

## 5. 一条消息的验收示例

以合成输入“请明天 15 点前把报价单发我”为例：

1. 已选来源发出通知，正文被保存并出现在对应 App 抽屉，同内容重放不增加新消息。
2. 已启用的 AI 提出“发送报价单”，保留时间短语、来源和原文证据；“明天”相对固定消息时间锚计算。
3. 用户在待确认中看到建议，可修改或忽略；确认前不出现在正式待办。
4. 用户确认后进入今天或全部中的相应分组，完成后移入已完成，重开 App 状态仍在。
5. 点击来源可看尚未过期原文，或请求打开原 App；历史入口失效时不打开另一个会话冒充成功。

对应负例“我明天把报价单发你”、对象不明确群聊、否定 / 条件句必须分别验证；任何时候都不能从“已打开微信”推断任务已完成。

## 7. 必须冻结的业务契约

- 消息、通知快照和待办分别有身份与溯源；不能按标题全局去重，不能把不同会话同文误合并。任务状态和用户编辑优先于 AI 重放。
- 待办四态为 CANDIDATE → CONFIRMED → COMPLETED，以及 CANDIDATE → IGNORED；本版不自动撤销完成或恢复忽略。
- 校验至少包含结构、证据、行动对象、时间精度和输入 / 配置版本；结构合法不等于语义正确，仍需质量评测。
- AI 只输出建议，不能执行通知内指令、发送聊天、选择未获准来源或直接完成任务。
- 抽屉关闭来源、点击入口失效、候选来源过期、模式变更各自有可观察状态；普通失败不隐藏成空列表。
- DB schema 变更带迁移；不静默清空原通知。运行时 PendingIntent 不落库 / 不进入 AI；普通日志不存正文 / Key。

细节以 [Phase 2 契约](MVP_PHASE2_PLAN.md)、[AI-C01–AI-C08](../product/AI/README.md) 和 MB 任务为准。本方案不另创建与 Kotlin / Room 相冲突的 DTO 或预占数据库版本。

## 8. 发布验收

所有条目当前均为 **NOT_RUN**，下表是拟定验收要求，不是已有能力。

| 编号 | 验收条件 | 证据 |
| --- | --- | --- |
| MVP-V01 来源边界 | 未选来源不读正文；关闭来源后不采集 / 推理；已提交正式任务保留 | NI 的 V01 / V02 与 AI-V03 的生产行为回归、真机来源操作 |
| MVP-V02 消息盒子 | 三款重点来源的受控通知进入正确抽屉，重复通知不抬高计数；重启保留查看状态 | MB-001；无正文 / 无通知 / 系统限制单独记录，不声称消息全覆盖 |
| MVP-V03 跳转 | 活跃入口打开来源定义的目标，历史失效有明确降级；无误投且不标记已回复 | MB-002 真机与可控来源回归 |
| MVP-V04 AI 候选 | 正例、负例、不确定、多行动、时间和证据符合冻结标签；失败与非任务分开 | P2-V01–V07、两真实引擎同集评测 |
| MVP-V05 任务生命周期 | 编辑确认 / 忽略 / 完成正确；重复提交 / 重启 / 迟到结果不重复、不覆盖用户内容 | P2-V08–V12、Room / 协程 / UI 证据 |
| MVP-V06 双模式边界 | 本地断网可推理且联网无通知外发；云端仅发送获准输入，模式切换不补发历史 | AI-V01–V10，目标 ARM 真机和合成真实服务 |
| MVP-V07 软件与交付 | Static / Verify 和相关 Device 通过，存在非空测试、迁移与设备 UI 证据 | 本次报告、代码 / APK 哈希、安装记录和已知限制 |
| MVP-V08 使用价值 | 完成短期自用，记录捕获 / 漏提 / 误报与整理耗时，用户确认有助于管理行动清单 | 试用报告；不足样本标不足，不能用演示代替 |

质量建议门槛（随本方案审核，TD-000 开始时冻结；不代表实测）：

- 独立验收集 200 条，80 行动 / 80 非行动 / 40 不确定，与开发样本分离；多行动逐项标注，来源与支持范围明确。
- 每个引擎分别达到候选 precision ≥95%、冻结支持场景内行动 recall ≥80%、明确截止字段准确率 ≥95%；同时单列全部样本结果，不通过删除困难样本或全部返回 UNSURE 达标。
- precision 分母为生成的所有行动建议，recall 分母为冻结范围内人工标注的应提行动项；缺失应提结果算漏项。超时 / 解析失败不从输入分母消失，另报失败率；模糊时间错误补成精确时间按错误计。
- 无证据建议不得进入候选；来源 / 配置竞态、跨会话误投、正文外发违规、数据库丢失或重复正式任务均为阻断问题，不以平均准确率抵消。
- 在 M0 固定短输入、设备与运行配置；热运行端到端 p95 ≤10 秒作为目标，计时从合格作业入队到结果持久化，另报冷加载、峰值内存、温度和失败。模型资源上限和可接受功耗依据目标设备在 M0 定值，冻结前不宣称可发布。

建议试用 7 天，人工对照至少 20 个应办事项；不足时明确样本不足并延长观察。分别记录“来源未发通知 / 正文不可见 / 采集失败 / AI 漏提”，不能把输入覆盖问题混入模型质量。记录每天确认 / 修改 / 忽略次数、整理耗时及是否减少遗漏；本轮不把短期小样本包装成全场景有效率。

最终产物为一份可安装的 debug APK（供受控试用）、模型与服务版本 / 配置说明、测试与试用报告、来源兼容性矩阵和未支持项。发布商店或分发到外部不包含在该交付动作中。

## 9. 风险与处理决策

| 发现 | 决策 |
| --- | --- |
| 关键任务多数没有可见通知 | 先记录覆盖差距，评审主动分享 / 官方来源接入，不继续靠调提示词补造内容 |
| AI 误报多、审核反而费时 | 缩小明确支持场景并报告影响，改提示 / 模型后重新测冻结样本；不隐藏失败或放宽标签 |
| 本地模型超内存 / 过慢 | 测量后更换已核验组合或收窄支持设备；两模式交付范围变更须明确记录 |
| 来源跳转只能到首页 | 将按钮标为打开 App，记录真实去向；不伪造会话直达 |
| 无法知道是否已回复 / 完成 | 保持用户手动确认和完成；回复内容采集不阻塞 MVP |
