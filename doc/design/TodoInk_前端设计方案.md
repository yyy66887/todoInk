## 1. 推荐方向

**一份有来源的纸质清单：通知先成为建议，用户确认后才进入待办。**

日常页面以清单为主，待确认页面以证据和决策为主。沿用现有 `PaperWhite / InkBlack / AccentPurple` 的识别基础，降低装饰密度，用留白、分组和字重建立层级。

首版集中解决三件事：今天有什么要做、哪些通知值得确认、这条建议从哪里来。提醒、日历排程、手工新建、AI 对话、设备与账号入口在相应功能阶段再设计。

## 3. 信息架构

```text
首次使用引导
  └─ 说明通知读取用途 → 前往系统授权 → 选择来源 → 完成

产品 MVP 底部导航（消息盒子与 AI 入口待实施）
  ├─ 待办（默认）
  │   ├─ 今天 / 全部 / 已完成
  │   └─ 待办详情 → 原通知（仍存在时）
  ├─ 待确认（数量角标）
  │   └─ 候选确认页 → 编辑标题 / 截止信息 → 确认或忽略
  ├─ 消息盒子
  │   ├─ 每个 App 一个抽屉 → 点击消息打开原 App
  │   └─ 独立详情操作 → 本地消息 / 原始字段 / 关联候选
  ├─ AI
  │   ├─ 模式与自动处理
  │   ├─ 本地模型 / 云端服务
  │   └─ 处理来源 / 处理记录
  └─ 设置
      ├─ 通知来源
      ├─ 采集状态与诊断
      ├─ 数据保留与清理
      └─ 关于
```

五个入口分别对应执行、确认、追溯、AI 处理和应用配置；采集状态在设置中。全局故障按来源分别引导查看“采集状态”或“AI”，不把模型异常显示成通知权限失效。

**与现状的衔接**：源码已实现“待办 / 待确认 / 通知 / 设置”四入口，前两页为真实空态，具体证据见 [STATE](../harness/STATE.md)。消息盒子由 MB-001 / MB-002 接入，五入口与 AI 子页由 AI-004 接入真实服务，不把静态表单或示例数据当成功能完成。

## 4. 页面设计

### P00 首次使用引导

- 一个说明页，标题“把通知里的事情，留在清单里”；三条简短说明：只读取你选择的来源、AI 处理方式由你选择、确认后才成为待办。明确默认不启用处理或上传，不能向云端用户承诺所有处理都在本机。
- 主按钮“前往开启通知访问”；次操作“稍后设置”，允许进入 App 查看空态。
- 返回 App 时重新读取系统授权；只有实际授权成功才进入选择来源。系统授权页由 Android 提供，不在 App 内仿造开关。
- 来源首次不预选；用户选择后显式保存。授权状态与来源配置不能用“监听已连接”代替。
- AI 自动处理默认关闭，在 AI 模块配置后独立开启，并说明“仅处理开启后收到的新消息”。旧预览为了演示闭环预置开启，不能沿用为生产默认值。

### P01 待办首页

从上到下：日期行 → “待办”标题 → 今天 / 全部 / 已完成分段筛选 → 有候选时显示“有 3 条待确认”入口 → 分组任务列表。

- **今天**：已确认且截止为今天或已经逾期；分为“已逾期 / 今天”。日期精度的任务到当地下一日才算逾期，精确时刻按保存的时区 / 时刻判断。
- **全部**：全部未完成正式任务；分组“已逾期 / 今天 / 之后 / 未设日期”，具体日期升序，同组同时间用创建时间 + ID 保持稳定顺序。
- **已完成**：按完成时间倒序；次级文案显示完成日期，不再标红旧截止时间。
- 行首 24 dp 可视圆圈包在至少 48 dp 点击区域内；标题 16 sp，最多两行；下方日期与来源 12–14 sp。点标题打开详情，点完成控件只提交完成操作。
- 待确认数量不计入待办数。不显示无意义的新增 FAB、完成率仪表或“连续打卡”。
- 完成成功后移入已完成；失败保留原行并提示重试。首版无撤销完成，不显示假的 Undo。正式任务详情首版只读，编辑能力限于确认前。

### P02 待确认收件箱

标题“待确认”，说明“来自通知的建议，由你决定是否加入清单”。按首次产生候选的时间倒序；来源图标 / 名称与发送人、标题建议、截止信息、最小原文证据形成一张卡片。

- 卡片主操作“查看并确认”，次操作“忽略”。不放完成圆圈，避免把候选误当已承诺的任务。
- 时间确定：显示“明天 15:00”；只有日期：显示“明天 · 未设时刻”；模糊表达：琥珀色“时间待确认”。颜色旁始终保留文字。
- 原文最多两行，点进确认页可阅读全文；不是完整聊天记录。隐藏会话 / 发送人时显示“发送人未知”，不猜测。
- “忽略”后候选退出列表，给出“已忽略，不会因同一消息重放再次出现”；无撤销按钮。首版不提供已忽略档案的恢复操作。
- 这里只展示执行对象明确的 ACTIONABLE 候选。执行对象不清的 UNSURE 留在通知详情显示“无法确定是否需要你处理”，不出现误导性确认卡片。
- 行动明确但时间模糊的候选仍可进入；确认页必须让用户明确选择日期 / 时刻，或“不设截止时间”。

### P03 候选确认页（全屏）

这一步包含阅读和编辑，采用全屏编辑页；日期 / 时间选择器再用系统风格弹窗。避免把长原文、键盘、多个表单都塞入半屏。

1. 顶部返回键 + “确认待办”。
2. 原通知证据区：来源、发送人、原时间、正文；仅高亮命中的行动和时间片段。
3. 标题输入：必填，去除首尾空白后不能为空；限制策略与 TD-001 一致，不在 UI 随意截断存储数据。
4. 截止精度选择：不设截止 / 仅日期 / 日期与时刻。模糊表达默认“请选择”，不能静默变成无日期或 23:59。
5. 原文时间提示：如“原文：下班前，具体时间需要你确认”；明确时间展示日期和采用时区，不写模型概率或“AI 置信度 95%”。
6. 底部主按钮“确认加入待办”，上方留出键盘和系统导航安全区。

提交中按钮禁用并显示“正在保存”；成功后返回待确认列表，提示“已加入待办”。失败保留草稿并提供重试；源候选过期 / 已被处理时提示并刷新，不覆盖已有正式任务。

返回且内容有修改时出现“放弃修改 / 继续编辑”；这属于 App 产品交互设计，不是本轮向开发用户申请许可。

### P04 正式待办详情

标题 → 确认状态 / 完成状态 → 截止信息 → 来源摘要 → “查看原通知”。已确认任务底部“标记完成”；已完成则显示完成时间且无可点击完成按钮。

原通知过期时显示“原通知已清理，待办仍保留”，取消原文入口但保留用户确认后的任务内容。不能把完整原文复制进描述字段来绕开清理。

### P05 消息盒子与 P06 消息详情

- 盒子首页按 App 展示抽屉：图标、名称、最近消息时间、最新摘要与“TodoInk 中未查看”计数。初次获准但无消息时展示空抽屉；关闭采集后仍在保留期内的历史抽屉标注“已停止采集”。同名 App / 不同用户资料不能混合归类。
- 展开抽屉后按最近观察时间倒序分日期；行内显示发送人或会话、时间、正文摘要。“正文不完整 / 仅摘要 / 内容不可用”作为可理解的次级标记。
- 点击消息行，使用该通知的有效跳转能力打开原 App；独立的“详情”操作查看本地内容，触控目标至少 48 dp。跳转失效时提示，并按可用能力提供“打开应用”或保留本地详情；不能保证进入特定会话，也不能误跳另一条通知。
- 未查看计数只代表 TodoInk 内查看情况：实际可见行、详情或点击操作按版本记为已查看，打开抽屉不批量消除屏外消息计数。重复通知不凭空增加数量。跳转和计数变化不表示已在原 App 阅读、回复或完成任务。
- 普通用户不默认看 packageName、notificationKey、hash 和解析器版本；这些保留在详情“原始字段”折叠区，满足 Phase 1 验收。
- 详情默认“整理内容”，展开完整消息与来源；“原始字段”可查看受控原始字段。Phase 2 追加关联候选 / 任务入口；非行动消息给出简短结果说明。
- 不使用下拉刷新暗示能拉取聊天历史；只显示实际最后收到时间与数据库刷新状态。

行为与验收归属 [MB-001 抽屉](../harness/tasks/MB-001-app-drawers.md)、[MB-002 跳转](../harness/tasks/MB-002-open-source.md)。不增加 TodoInk 内回复框。

### P07 设置、P08 来源与 P09 采集状态

- 设置分组：“采集”“数据与隐私”“关于”；消息处理和模型配置集中到 AI 模块，无账号头像、订阅、蓝牙设备占位。
- 来源页：搜索本机可配置应用 + 名称 / 图标 + 开关；保存成功才反馈。当前仅列可启动应用的限制如实说明，不暗示覆盖所有包。
- 状态页分开显示“通知访问：已授权 / 未授权”和“监听服务：已连接 / 未连接 / 状态未知”。最近收到、最后保存、丢弃 / 失败摘要属于次级诊断区。
- 异常入口：未授权→“前往系统设置”；已授权未连接→“查看恢复步骤”；没有任何来源→“选择通知来源”。恢复是否成功以实际事件验证。
- 保留期只提供 Repository 真正支持的选项；原型以 7 天为演示值，不变更业务默认。清空操作明确影响通知、关联消息和未确认候选，正式任务保留；显示影响范围后再由用户确认。
- 原“本地候选识别”设计由 AI 模块的模式与自动处理开关替代，设置页不重复控制。关闭处理不删除正式任务；隐私说明按实际模式显示。

## 5. 视觉规范

### 色彩与层级

沿用现有三项颜色，扩充语义色。表中是设计 token 建议，实施时统一映射 `MaterialTheme.colorScheme`，页面不散落硬编码。

| Token | 浅色 | 深色建议 | 用途 |
| --- | --- | --- | --- |
| background | `#F7F3EE` | `#181719` | 纸感底色 |
| surface | `#FFFCF8` | `#242226` | 卡片 / 输入区 |
| onSurface | `#1C1B1F` | `#F1EDF3` | 主文本 |
| secondaryText | `#69636F` | `#C1BAC6` | 来源与说明 |
| primary | `#6750A4` | `#D0BCFF` | 确认按钮 / 导航选中 |
| onPrimary | `#FFFFFF` | `#241544` | 主按钮文字 |
| primaryContainer | `#EEE7F7` | `#3A2C52` | 轻强调入口 |
| outline | `#DAD3DF` | `#4D4654` | 分隔与输入边界 |
| warning / container | `#875900` / `#FFF1D6` | `#F4CC80` / `#3C2F18` | 模糊时间 / 待处理异常 |
| error / container | `#A83735` / `#FCE9E6` | `#FFB4AB` / `#492522` | 逾期 / 保存失败 |
| success / container | `#35624F` / `#E5F0E9` | `#A4D3BA` / `#22392D` | 实际完成 / 实际连接 |

品牌强调色保持紫色，来源品牌色只用于小图标，不能把每张卡片染成不同背景。纸感通过底色实现，不使用纸纹图片。设计稿不引入插画、照片或联网字体。

### 字体、尺寸与组件

| 项目 | 规范建议 |
| --- | --- |
| 字体 | Android 系统字体与中文 fallback；不额外打包商业字体 |
| 页面标题 | 28 sp / 36 sp，Medium 或 SemiBold |
| 任务标题 | 16 sp / 24 sp，Medium；详情可换行 |
| 正文 / 表单 | 14–16 sp / 22–24 sp |
| 来源 / 时间 | 12–14 sp / 18–20 sp；不能为塞满卡片而缩字 |
| 间距 | 4 / 8 / 12 / 16 / 24 / 32 dp；页面左右 20 dp |
| 卡片 | 16 dp 圆角、16 dp 内边距；普通任务用行与分隔线 |
| 主按钮 | 最小高 48 dp；建议 52 dp，圆角 14 dp |
| 图标 | 24 dp 线性图标；48 dp 点击范围 |
| 导航 | 新版 5 项图标 + 标签（含 AI）；选中使用浅紫容器，角标最多 99+；须验收窄屏与大字体 |
| 动效 | 建议 150–220 ms 淡入 / 状态变化；响应系统减少动画设置，无庆祝飘落动画 |

所有触控目标至少 48 dp，操作不依赖滑动手势；遵循 [Android 无障碍设计建议](https://developer.android.com/design/ui/mobile/guides/foundations/accessibility)。普通文字对比度目标 ≥4.5:1，不能只靠颜色表达错误或状态。

### 适配

- 设计预览以约 390 dp 手机宽度表达；实施检查 360 / 390 / 412 dp，最小 320 dp 窗口也不能横向溢出。
- 文字缩放 200% 时卡片、按钮与导航允许增高；来源 / 长标题优先换行，不能挡住确认按钮。
- Edge-to-edge 使用系统栏 insets，编辑页处理 IME；底栏不覆盖最后一条任务。
- Phase 2 首版优先手机。横屏 / 分屏先保持单列并限制内容最大宽度；大屏列表详情双栏另列后续适配，不为了效果图新增复杂响应框架。
- 深色跟随系统；预览可切换浅 / 深用于审核 token，真实设备对比度和 TalkBack 仍需单独验收。

## 6. 必须设计的状态

| 状态 | 用户看到的内容 / 操作 |
| --- | --- |
| 没有今天任务 | “今天没有到期任务”；如有其他任务给“查看全部”，不假称所有事情完成 |
| 没有待确认项 | “暂时没有待确认”；识别关闭时给“前往开启”，开启时说明新通知产生建议后显示 |
| 还没授权 | 消息盒子“开启通知访问后，才能收到所选应用的通知”；按钮进入系统设置 |
| 已授权但没选来源 | “先选择通知来源”；按钮进入来源页 |
| 授权但服务未连接 | 黄色提示；保留已存数据可浏览；不显示“正在同步聊天” |
| 加载中 / 读取失败 | 初始轻量占位；失败保留旧数据并给重试，不把失败显示成空列表 |
| 标题为空 | 字段内提示“请填写待办标题”；保存不发出 |
| 时间模糊未选择 | 提示选择精度 / 日期，或显式不设截止；不能自动填具体时刻 |
| 正在提交 | 仅相关操作禁用；重入点击不增加请求 |
| 已处理 / 来源已过期 | 保留解释并返回刷新；不重新创建候选 |
| AI 处理异常 | 消息仍可查看；提示该条暂未生成建议并进入 AI 记录，不假装非任务或处理成功 |
| 原消息跳转失效 | 保留本地详情；按实际能力提供“打开应用”或“暂无法打开”，不标记已回复 |
| 关闭来源 | 后续符合取消边界的处理不写入；已确认任务与已有数据按原保留策略处理 |

旧版预览覆盖核心浏览、确认、忽略、完成、来源筛选、设置、模糊时间校验和主题切换；尚未加入 AI 页面。系统权限、数据库竞争、进程恢复、读取失败等由实际实现验收，预览不模拟为真实系统成功。

## 7. Android 前端落地

- 保留 Compose Material 3 / Navigation Compose / Hilt。预览是浏览器演示文件，不是 WebView 或 React 技术选型。
- Route / Screen 维持现有约定：Route 收集 ViewModel 状态；Screen 接受不可变 UiState 和事件。列表、详情分别有 Loading / Content / Empty / Error；提交状态不与整页加载混用。
- 建议共享组件：`TodoRow`、`CandidateCard`、`SourceBadge`、`DueLabel`、`EvidenceBlock`、`StatusBanner`、`EmptyState`、`ConfirmActionBar`；只在第二处复用出现时提取，避免先建庞大组件库。
- 候选详情经候选处理服务提交；列表读 Repository 的展示模型。不在 Composable 判断 ACTIONABLE、计算去重、直写 Entity / DAO 或重新按当前时间解析“明天”。
- 日期格式化只负责显示：底层保留时间精度 / 锚点 / 时区；已过去显示具体日期，“仅日期”不生成隐藏提醒。
- `rememberSaveable` / ViewModel 保存筛选、列表位置与编辑草稿；弹出编辑页恢复来源列表位置。用户离开修改页时按 P03 处理。
- 列表采用稳定业务 ID；确认 / 忽略 / 完成以数据库实际结果驱动 UI；导航返回不重新执行写入。
