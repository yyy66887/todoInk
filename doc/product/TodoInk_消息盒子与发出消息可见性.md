# TodoInk：消息盒子与发出消息可见性

- 日期：2026-09-22；版本：v0.1；状态：产品方向修订与技术研判，未实施。
- 用户明确选择：不采用 TodoInk 内直接回复；增加消息盒子，按获准 App 分抽屉，点击消息跳转原 App，由用户在那里回复。
- 本文替代 [旧直接回复研究](TodoInk_跨App回复可行性评估.md) 的产品建议；旧文仅作历史参考，不继续推进 RemoteInput 发送。
- 关联：[前端方案](../design/TodoInk_前端设计方案.md)、[AI 模块](AI/README.md)、[当前交接](../harness/STATE.md)。

## 1. 明确结论

**消息盒子和点击跳转可实现；仅凭现有通知访问权限，不能可靠、完整地采集用户在其他 App 内发出的消息。**

通知监听接收的是来源 App 发布 / 更新 / 移除的通知，不是跨 App 的聊天收发事件。Android 的应用沙箱隔离各 App 私有数据；从 TodoInk 打开微信等 App，不会因此获得其聊天数据库、输入框或“发送完成”的通用回调。[通知监听 API](https://developer.android.com/reference/android/service/notification/NotificationListenerService)、[Android 应用沙箱](https://source.android.com/docs/security/app-sandbox)

因此消息盒子应描述为“你允许收录的通知”，而非完整聊天记录。用户正在原 App 聊天、来源未发通知、通知内容被隐藏或监听断开时，都可能缺消息；AI 不能把缺失内容补成真实记录。

## 2. 抽屉式消息盒子

将现有“通知”入口升级为“消息盒子”，不是新增另一个重复通知页。既有方案中“通知列表 / 通知详情”对应本方案的抽屉列表 / 通知详情；AI 和待办入口保持原职责。

```text
消息盒子
  ├─ 微信抽屉：待查看数量 / 最新摘要 → 通知列表 → 打开微信
  ├─ 企业微信抽屉：待查看数量 / 最新摘要 → 通知列表 → 打开企业微信
  └─ QQ 抽屉：待查看数量 / 最新摘要 → 通知列表 → 打开 QQ
```

- 只收录系统通知访问权限有效、且在 TodoInk 内被用户选中的来源。Android 通知访问授权与 TodoInk 自己的来源允许列表是两个层次。
- 每个来源 App 一个抽屉，包名作为基本归属；涉及应用分身 / 工作资料时额外隔离用户资料，不能仅用显示名称合并。
- 抽屉展示来源图标、名称、最新消息摘要及“TodoInk 待查看”数量。这个计数不冒充来源 App 的未读数。
- 抽屉内按最新观察时间排列，保留发送人 / 群名（有依据时）、摘要、时间和来源详情。没有可信会话标识时不把同名消息合并为聊天线程。
- 来消息后更新抽屉，不自动拉起来源 App；用户点消息才跳转。保留查看原文 / 来源字段的入口。
- 停止收录某 App 后停止新增，既有内容按原保留期展示并注明“已停止收录”；已有正式待办不因关闭来源而删除。

## 3. 一键跳转的真实边界

优先使用当前通知提供的 `contentIntent`，效果由来源 App 定义，可能打开相应会话，也可能只打开列表或首页。`contentIntent` 是通知点击入口，不包含“回复后回传内容”的通用契约。[Notification API](https://developer.android.com/reference/android/app/Notification#contentIntent)

实现建议：用户前台点击 → 复核来源和当前通知身份 → 获取仍有效的点击入口 → 执行跳转。入口缺失 / 失效时降级为“打开 App”，不可用时明确提示；不承诺历史通知永远能直达原会话。运行时 PendingIntent 留在系统适配层，不序列化到 Room。系统启动限制和来源行为需真机验证。

TodoInk 可以可靠记录用户自己的“已查看”和“已请求打开”操作，但一次调用或 Activity 恢复不能证明正确会话已展示。只有用户手工选择时，才记录“用户标记已处理”。不能根据跳转、停留时间、返回 App 或通知移除推断“已回复”。

## 4. 哪些情况下可能看到发出的内容

| 获取方式 | 能得到什么 | 结论 |
| --- | --- | --- |
| 仅监听通知 | 来源实际发布的通知字段 | 对方通知可收录；用户自己发出的消息没有必然通知 |
| 来源通知附带 MessagingStyle 自己的消息 | 部分发出内容或会话上下文 | 可作为有来源的补充观测，依赖 App 实现；不代表完整历史或送达 |
| RemoteInput 历史字段 | 来源填写的通知快捷回复历史 | 不等同用户进入原 App 后发送的历史，本方案不依赖它 |
| 官方接口 / 平台授权同步 | 接口允许范围内的消息和状态 | 需逐平台验证双向事件、账号身份、权限和会话范围，不是通用通知权限 |
| 用户主动分享、复制导入或补充说明 | 用户明确提交的文本 | 可行，但标注“用户补充”，不能直接称为真实发送记录 |
| 额外授权的无障碍页面读取 | 页面实际暴露的节点与可见文字 | 某些 App 可尝试；适配脆弱，无法通用证明已发送 / 已送达，首版不依赖 |

Android 的 MessagingStyle 支持在通知中表示当前用户的消息；但是否填入、是否在用户从 App 内发送后更新通知，由来源 App 决定。微信 / 企微 / QQ 的该行为尚未实测。[MessagingStyle.Message](https://developer.android.com/reference/android/app/Notification.MessagingStyle.Message)

`EXTRA_REMOTE_INPUT_HISTORY` 的文档定义是该通知 RemoteInput 的近期输入，由 App 提供并可清理。不能把它当成普通聊天窗口发出消息的记录接口。[通知回复历史字段](https://developer.android.com/reference/android/app/Notification#EXTRA_REMOTE_INPUT_HISTORY)

无障碍服务在配置并获准后可以读取可访问窗口内容，但实际节点、控件结构和文字可见性受目标页面实现影响；“输入框出现文字”只证明编辑，“看见发出的气泡”也不保证服务器已投递。使用情况权限提供应用使用事件，不能提供聊天文本。[AccessibilityService](https://developer.android.com/reference/android/accessibilityservice/AccessibilityService)、[UsageStatsManager](https://developer.android.com/reference/android/app/usage/UsageStatsManager)

若后续评估无障碍读取，应单列用途、用户授权、目标 App 适配及发布渠道要求，不能把它悄悄附加到通知访问权限中；普通应用还须满足相应披露与使用规则。[Google Play 官方政策](https://support.google.com/googleplay/android-developer/answer/10964491?hl=en)

## 5. 对 AI 和数据模型的影响

AI 可以根据收录的通知生成待办建议，但当前不能据此自动认定用户承诺了某事、已经回复或完成待办。例如收到“明天能交吗？”后跳转，用户可能回复“可以”“做不了”，也可能没有回复；这三个结果不能由跳转记录区分。

拟定数据语义应分开：来源通知 / 通知附带的自己消息 / 用户补充；方向为收到 / 发出 / 未知，附判断依据。当前 `ParsedMessage` 只有 senderName、text、messageTimestamp，不能仅凭 senderName 为空就判定“我发送的”——当前投影已经丢失了是否有 Person、消息所属用户等区别。保留必要原始语义和明确来源后，才能做方向适配；缺证据保持未知。

新增页面状态建议只包括：待查看、已查看、已请求打开、用户标记已处理。来源通知撤除单独记为“当前通知已失效”；消息处理状态、AI 提取结果和待办完成状态保持独立。“已回复”或“已送达”未来只能来自明确的用户声明或经过验证的平台事件，并标明依据。

## 6. 建议实施与验证范围

1. 先实现消息盒子的 App 抽屉、通知列表与既有来源设置联动，复用 NI 的采集 / 去重 / 保留期，不重建监听器。
2. 添加当前通知点击能力管理及移除 / 断连 / 来源关闭的失效处理；验证有效通知、历史失效通知和多会话摘要的跳转去向。
3. 三款目标 App 分别用用户选定的测试会话验证：收到通知 → TodoInk 点击跳转 → 在原 App 回复 → 返回 TodoInk。只核对是否出现新的通知字段，不把“没观察到”当成“没有发送”。
4. 只有观察到有来源、可区分方向的回显，才设计可选的发出内容补充；未观测到时，首版保持“通知收录 + 用户标记 / 主动补充”。

全部功能和真机验证目前 **NOT_RUN**。本轮只修订产品与研究文档，没有增加任何采集权限、读取私人聊天或操作联系人。当前已经决定取消直接回复产品路线；无障碍、平台接口和全量双向同步都未纳入实施范围。
