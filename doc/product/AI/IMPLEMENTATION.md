## 1. 工程接入

继续使用单 `:app`、Kotlin / Compose / Room / Hilt。以下是拟定职责位置，实施时再在检查器中登记确切依赖，不提前放宽规则。

| 位置 | 职责与边界 |
| --- | --- |
| `ai.api` | 平台无关的提取请求、结果、引擎端口和错误；不引用 Room、UI、HTTP 或模型 SDK |
| `ai.validation` | 结构 / 证据校验，结合 TD-004 时间结果；不写数据库 |
| `ai.local` | 模型文件与运行时适配、加载 / 取消 / 释放；不依赖云端客户端 |
| `ai.remote` | 兼容协议、请求构造、凭据使用和响应解析；不直接写候选 |
| `data.settings` | 模式、来源、配置版本与受保护的密钥引用；不执行推理 |
| `data.repository` | 消息读取、作业 / 候选原子提交、用户编辑保护、保留期 |
| `processing` | TD-005 的应用服务：来源准入 → 选定引擎 → 校验 → Repository 提交；不持有 Notification / Bundle |
| `ui.ai` | 页面状态、表单、测试和控制事件；通过应用服务 / Repository 操作，不直连 DAO |
| `di` | 装配端口与具体引擎；推理和 HTTP 逻辑不放入 Hilt module |

`processing` 依赖 `ai.api` / 校验、Repository 与 Settings；具体引擎依赖端口，Repository 不反向调用引擎。时间解析保持纯逻辑，可供校验与候选编辑共用。接口命名是设计建议，不先维护一份与 Kotlin 冲突的可编译伪 DTO。

云端实现将新增网络权限和最小 HTTP 依赖；本地实现新增选定运行时 / 原生库及 ABI 配置。每个新增依赖记录版本、许可、引入目的、替换或移除条件。模型权重独立下载 / 导入，首版不直接打包进 APK，且不把任意未验模型显示为已支持。

Room 迁移在 TD-001 上扩展消息、提取记录 / 作业和待办，模型文件保存在应用私有文件目录，密钥不存明文数据库。数据库版本以实施时现有 schema 为起点，不在方案中预占“v2 / v3”。备份规则须覆盖新增文件，卸载模型、清理原文与删除 Key 的生命周期各自明确。

## 3. 五项新增实施任务

下列 AI-001–AI-005 是正式任务索引，集中在本页记录范围和验收；实施时按 [任务模板](../../harness/templates/task.md) 建立对应执行记录。旧可行性评估中的 AI-0–AI-4 只是研究批次名，以本表为准。

| ID / 状态 | 交付与依赖 | 完成判据 |
| --- | --- | --- |
| AI-001 / DRAFT | 模式 / 来源 / 配置版本、引擎选择、受保护凭据及准入控制；依赖 TD-001 / TD-003 契约，可先用合成引擎 | 关闭无推理，LOCAL 无云端调用；配置切换使旧任务失效；凭据无明文持久化 / 日志；生产代码回归通过 |
| AI-002 / DRAFT | 云端适配器、合成测试、超时 / 限流 / 配额与能力检测；依赖 AI-001 | 一种兼容服务与真实测试 Key 跑通合成提取，错误分类正确；不得通过假响应宣称服务已可用；重定向、格式错误和结果未知超时均受控 |
| AI-003 / DRAFT | 本地组合技术验证、模型管理与推理引擎；依赖 TD-000 / TD-003，产品接线依赖 AI-001 | 在目标 ARM 真机选择并锁定一个模型 / 量化 / 运行时组合；断网可提取，资源 / 温控 / 回收验证通过，实测数据完整 |
| AI-004 / DRAFT | P10–P14 页面、五入口导航、候选 / 通知联动；依赖 AI-001 和 TD-005 / TD-006，最终依赖两个真实引擎 | 表单、状态、隐私文案、失败和重试与真实后台一致；仅完成 UI 不能标记本项 DONE；设备走查通过 |
| AI-005 / DRAFT | 双引擎同集评测、外发边界 / 切换竞态 / 成本 / 资源验收；依赖 AI-002 / AI-003 / AI-004、TD-007 及相关 NI | AI-V01–AI-V10 完整证据，联合 TD-008 完成端到端双模式验收；任一路线未验证则双模式未完成 |

任务依赖保持上表；实际交付按产品 MVP-M0–M4：先稳定消息 / 抽屉与共用契约、配置，再接首个真实引擎 → 候选 / 待办闭环 → 补齐第二引擎与完整 AI 页面 → 双模式联合验收。本地组合技术验证可在契约与设备就绪后提前，不必等待云端或 UI 完成；不要求多 Agent。

把云端安排在前面是尽早验证接口和效果基线，两种模式都是最终交付范围。设备 / Key 暂不可用时仍可完成纯校验、受控客户端和合成流水线，但不得把这些检查当成真实引擎通过。

## 4. 验收矩阵

| ID | 操作 | 必须观察到的结果 / 环境 | 当前 |
| --- | --- | --- | --- |
| AI-V01 | 关闭模式；LOCAL 引擎失败 | 无云端请求，通知采集继续；生产调度器与受控网络边界 | NOT_RUN |
| AI-V02 | 本地模型安装后飞行模式运行，联网再次运行 | 同一固定合成集可提取；联网抓包 / 网络观测无通知外发；目标 ARM 真机 | NOT_RUN |
| AI-V03 | 各来源组合、关闭来源、修改服务后放行发送 | 未获准内容不发送；已发送无法撤回如实记录；受控发送准入竞态测试 | NOT_RUN |
| AI-V04 | 错 Key、429、断网、超时、重定向、非法 JSON、拒绝 / 截断 | 错误可区分，无错误语义成功 / 无限重试 / 跨域凭据发送；受控 HTTP + 合成真实服务 | NOT_RUN |
| AI-V05 | AI 返回无证据行动、编造日期、注入要求执行工具 | 校验拒绝或待判断，无工具执行、无额外外发；直接调用生产校验器 | NOT_RUN |
| AI-V06 | 处理期间切模式 / 关闭，迟到响应；候选提交前后中断 | 配置版本生效边界可验证，无旧结果写入、无重复候选、用户编辑保留；Room + 可控协程 | NOT_RUN |
| AI-V07 | 模型文件损坏、加载失败、内存压力、持续处理、后台回收 | 明确错误 / 暂停，采集保持工作；冷 / 热延迟、PSS、温度与耗电测量；真机 | NOT_RUN |
| AI-V08 | 用尽配额、未知用量、结果未知超时后重启 | 配额不因重启清零；不自动重复计费式重试；费用未知不伪装为零 | NOT_RUN |
| AI-V09 | 检查日志 / 备份、密钥删除、模型卸载、原文保留期到期 | 无 Key / 正文泄漏；正式任务保留；缓存不延长私密原文寿命；配置审查 + 设备 | NOT_RUN |
| AI-V10 | 两引擎各完成通知 → 候选 → 编辑确认 → 完成 → 重开 | 同一业务状态契约成立，各有真实引擎 / 设备与版本证据；联合 P2-V01–V12 | NOT_RUN |

实现时最低软件门禁为 Static / Verify，涉及存储、设备与 UI 的项补 Device / 手工真机证据，见 [验证矩阵](../../harness/VERIFICATION.md)。模型行为非确定性，生产校验 / 调度用可控输出回归，真实模型另以冻结样本测效果，不能用桩替代质量验收。

质量评测建议使用独立 200 条样本（80 行动、80 非行动、40 不确定），优先合成和脱敏数据。规则对照、本地模型、云端模型使用同一标签与口径，分别报告准确率 / 召回率、不确定比例、证据错误、时间精度和失败比例，明确分子分母。原 60 条可用于早期冒烟，不作为双模式最终质量结论。

可行性评估中的准确率与 p95 等数字仍为待冻结目标，未实测；AI-001 开始前结合 TD-000 样本和目标手机记录发布门槛，不能临近验收放宽。目标手机的 RAM、可用空间、实际模型文件大小和后端兼容性待核实，历史通知测试真机通过不证明本地模型可运行。

## 5. 触发重审的条件

如本地组合在目标设备上无法同时达到可用质量与资源要求，应提交实际对照证据，调整支持机型 / 模型或产品范围；不得默默删除本地模式或自动改走云端。需要直接生成正式待办、历史批量重算、跨服务自动故障转移或云服务器时，另补产品契约及验收后再实施。
